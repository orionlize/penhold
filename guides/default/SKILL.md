# penhold-mcp 默认设计规范

本规范是兜底方案：项目里有设计 skill、`DESIGN.md` 或用户给了品牌规范时，以那些为准。用户在对话里的明确要求永远优先于本规范和预设。

## 1. 先确定主题，再动手

开始前先想清楚三件事：**这是什么产品**、**给谁用**、**这一页的主要任务是什么**。用户没说清楚时（例如只说“画一个登录页”），不要自己假设后直接开始画：调用 `design_ask()` 在画布上展示问卷，让用户选择视觉方向、主色和页面内容。即使用户说清了产品与内容，**视觉偏好也要先问**：不要自己挑方向卡片、生成设计系统或配色（问过之前服务端会拒绝这些调用）；只有用户亲口说过风格、颜色、明暗或参考产品时，才在 `design_plan` 的 `user_style` 里原样转述后跳过问卷；可以传 `questions` 追问你最想确认的几件事。用户回答后按回答设计，页面内容以用户勾选和填写的为准；用户点了“跳过，让 AI 决定”（`status:"skipped"`）时，才自己提出一个具体的假设（如“面向 25–35 岁上班族的记账 App，首页的任务是一眼看清本月结余”），在回复里说明，再继续。问卷还没提交（`status:"waiting"`）时告诉用户去画布上填写，再次调用 `design_ask()` 等待，期间不要绘制。行业、题材和用户群的语汇是做出有辨识度的设计的来源：给 8–11 岁孩子的识字 App 和给财务分析师的看板，在色彩、字号、密度、圆角上都应该明显不同。全程使用贴近真实的内容，不用 “Lorem ipsum”“标题一”“按钮”。

## 2. 设计系统：先有系统，再画页面

设计依据是一个**项目级的设计系统**，与画布分开保存，同一项目的所有画布共用：颜色按亮 / 暗主题各存一个值并写明用途，文字是“字号 + 行高 + 字重 + 字体”的组合样式，另有间距、圆角、阴影、组件和一份品牌手册 README。

- **项目已有系统**（`canvas_open` / `design_plan` 返回 `design_system`）：先用读文件工具完整读它的 README，照它画，不再选方向卡片；首次写入时自动安装到画布。文本节点从 `text_styles` 里选一种样式，把它的字段原样写进 style；系统里有的组件直接实例化，不画仿制品。
- **项目里有样式代码**（CSS 变量、shadcn / Tailwind 主题、Claude Design 的 tokens.json）：`design_system({action:"import", path})` 从代码导入，取值照抄，不近似、不臆造。导入值里对比度不达标的只列出来，告诉用户，经同意再改。
- **都没有**：按下文选一张方向卡片，再 `design_system({action:"create", name:"<产品名>"})` 生成一个小而完整的系统（两套主题、按方向密度的字阶与文字样式、间距、圆角、阴影、品牌说明），对比度已修正，自动安装。
- **改系统，不改画布**：缺一档令牌、要调颜色或字重时用 `design_system({action:"update", patch})` 改系统本身，所有画布一起生效；只在一个画布里 `tokens_set` 会和系统走散（返回 `system_drift` 提醒）。画好的按钮、输入框、列表项等可复用块用 `design_system({action:"save_components", names})` 存进系统。
- 系统的浏览页（`design_system` 返回的 `page`）展示各主题色板与对比度、文字样式、组件预览，交付时附给用户；`design_system({action:"export"})` 把它写到项目的 `design-system/` 目录（含给前端用的 tokens.css），提交进仓库后其他机器自动发现。

## 3. 没有系统时：先定设计方向

还没调用 `design_plan` 的话先调用它，让画布先显示骨架屏。它的返回值里有两样东西要用上：

**`design_directions`：设计方向卡片。** 用户在问卷里选定了视觉方向时，`design_ask` 已返回完整方向（`direction`）并记到画布上，直接用它的 `tokens`，跳过下面的选卡步骤；用户另外指定了主色或明暗时按用户的调整。用户没有选（或跳过问卷）时，`design_plan` 返回 3 张差异明显的方向，每张包含风格原型、色板、字体搭配、形状与层次、版式思路和一个记忆点。需求越短（“画一个登录页”），越要靠它来避免退回惯用的默认配色与版式。

1. 结合第 1 节想清楚的产品、用户与任务选一张。`basis` 标为“贴合题材的常规解”的是稳妥方案；没有明显更合适的，就选与常规解不同的那张。都不合适时调用 `design_direction()` 换一批。
2. 调用 `design_direction({pick:"<卡片 id>", concept:"…", motif:"…"})`。`concept` 用一句话写出这一稿与众不同的那一点（如“把本月结余做成首屏唯一的大数字”）。`motif` 是题材母题：从这个题材里取一个具体的物、形状或数据形态，并说明记忆点怎样用它来画（钓鱼 App：“浮漂与水线，出钓指数画成浮在水线上的浮漂刻度”；记账 App：“小票，本月账单做成一张撕口的小票”）。方向卡片的记忆点只是构图手法，换任何题材都一样；有了母题，这一稿才属于这个题材。用户在问卷里选了方向时也要补这一步（返回里有 `motif_missing` 就是还没补）。返回完整方向并记到画布上，之后同一画布再打开时沿用。
3. 返回内容的用法（选定后调用 `design_system({action:"create"})` 把它们存成系统并安装，不必手动 `tokens_set`）：
   - `tokens`：颜色、字体、圆角、阴影令牌；建系统时会补上字号、间距与文字样式。`font.*` 已按本机安装的字体生成，直接使用。
   - `typography`：这个方向下标题与正文各用什么字体、哪几档字重。
   - `signature` + `motif`：记忆点的构图手法与它画的内容，要在每个页面里真正画出来，而不是只写在计划里。
   - `palette_note`：出现时说明色板不是按本题材挑的。从题材里真实存在的颜色取一个主色，再调用一次 `design_direction({pick, primary:"#RRGGBB"})`，整套色板按它重算并修正对比度。用户指定了主色时同样这样做。
   - `example`：这个方向下一张完整的移动端首屏（题材与你的需求无关）。学它怎样用字号阶梯加一处展示级大字、怎样控制粗体、怎样分形状层级、怎样把记忆点真的画出来；不要照搬它的内容、构图和区块顺序。
   - `shape` / `layout`：形状、层次与版式取向，全稿保持一致。
   - `avoid`：这个方向下不要做的事。
4. **方向是起点，不是成品**。用户指定了颜色或风格就以用户为准，方向里对应的部分照改。改动后检查正文与背景对比度不低于 4.5:1，大字（≥ 24px 或 ≥ 18.67px 粗体）不低于 3:1。

**`page_guides`：页面类型规范片段。** 按本轮页面的类型（登录、首页、看板、落地页、列表、详情、表单、个人中心、引导 / 结果页）给出几种构图方案与常见平庸写法。每类从构图方案里选一个，不要默认用第一个；列出的平庸写法至少避开。

需要某个具体行业的色板或落地页 / 看板结构时，仍可用 `design_preset({query:"food delivery app"})` 查产品类型预设（英文关键词更准），`design_preset({id, use:true})` 取详情。

## 4. 先写设计计划，再复核

动手绘制前，在心里（或回复里简短地）列出：

- **色彩**：4–6 个具名颜色及用途。
- **字体**：一到两个字体族及各自角色；用两个时要明显不同。
- **版式**：布局思路、对齐方式（左对齐、居中还是两端），信息密度。
- **原则**：这一页与众不同的那一点是什么。

然后对照下面这些“AI 生成稿的常见默认特征”复核。它们并非不能用，而是在任何题材上都会出现，因此是默认而不是选择。需求没有指定时，不要把自由度花在它们上面：

1. 暖米色背景（约 #F4F1EA）+ 高对比衬线大标题 + 赤陶色强调（约 #D97757）；
2. 近黑背景 + 单一荧光绿或朱红强调；
3. 报纸式版面：细线分隔、零圆角、密集分栏；
4. “SaaS 卡片套件”：内容切成一模一样的圆角卡片，所有层级用同一个圆角和同一个浅灰阴影，渐变只作装饰；
5. 模板化细节：每个标题上方都有字距拉开的全大写小标签、“A · B · C” 式元信息、“词 — 片段” 式标签、#111 代替纯黑、用等宽字体写小数据标签、链接和按钮文字后面加 “→”。

计划中哪一部分换个类似需求也会得到同样结果，就改掉那一部分。

## 5. 令牌约定

有设计系统时令牌由系统安装，本节只说明命名与取值约定；没有系统时先用 `tokens_set` 一次性定义令牌。节点里一律用 `{color.primary}` 这样的引用，不直接写色值。字体写 `fontFamily: "{font.heading}"`；渐变与阴影里的颜色也写令牌，如 `linear-gradient(90deg, {color.primary}, {color.accent})`、`0 0 16px {color.primary}`。需要半透明或深浅变体时，先加成令牌（如 `color.primary-soft`）再引用。

| 类别 | 令牌名 | 说明 |
|---|---|---|
| 颜色 | `color.primary` `color.on-primary` `color.secondary` `color.on-secondary` `color.accent` `color.on-accent` | 主色、次色、强调色及其上的文字色 |
| | `color.bg` `color.fg` `color.card` `color.card-fg` | 页面背景与正文、卡片背景与卡片文字 |
| | `color.muted` `color.muted-fg` `color.border` `color.ring` | 弱化背景、次要文字、分隔线、焦点环 |
| | `color.danger` `color.on-danger`，按需加 `color.success` `color.warning` | 状态色 |
| 字体 | `font.heading` `font.body`，按需 `font.mono` | 字体族，带回退，见下文 |
| 字号 | `size.xs` `size.sm` `size.md` `size.lg` `size.xl` `size.2xl` `size.3xl` | 字号阶梯 |
| 间距 | `space.1` … `space.8` | 4 的倍数：4 8 12 16 24 32 48 64 |
| 圆角 | `radius.sm` `radius.md` `radius.lg` `radius.full` | 按层级区分，不要所有元素一个圆角 |
| 阴影 | `shadow.sm` `shadow.md` | 只用于确实浮起的层（弹窗、浮动按钮、下拉） |

**字号阶梯**（px）：移动端 12 / 14 / 16 / 18 / 22 / 28 / 34；桌面端 12 / 14 / 16 / 20 / 24 / 32 / 48（设计系统按方向的信息密度会更紧或更松，以系统为准）。正文 14–16，行高 1.5–1.7；标题行高 1.2–1.35。

- 节点的 `fontSize` 只写 `{size.*}` 令牌，不写 13、15 这类夹在两档之间的数字：差 1–2px 看不出层级，只会让页面发散。唯一的例外是比最大一档还大的展示级字号（首屏的大数字、大标题），一页最多一处。
- 每页要有一个明显的焦点：最重要的标题或数字至少是正文的 2 倍。
- 字重只用两三档。粗体（600 以上）只给标题、关键数字和主按钮，不超过全页文字的三分之一；标签、列表项、辅助信息用 400 / 500。处处加粗等于没有重点。

**字体**：画布按本机已安装的字体渲染，不会在线加载。优先用 `design_direction` 返回的 `font.heading` / `font.body`（/ `font.mono`）：它们只包含本机装了的字体，并按方向给标题选了宋体、楷体、圆体或黑体，与正文的黑体形成对比。不要为了“更有设计感”写本机没有的字体，那只会回退成默认字体并被自检报错。自己写 `fontFamily` 时，中文界面必须带中文字体，并以通用族名结尾：
- 无衬线：`"PingFang SC, Noto Sans CJK SC, Microsoft YaHei, sans-serif"`
- 衬线：`"Songti SC, Noto Serif CJK SC, serif"`

标题与正文是同一个字体族时，层级只能靠字号与字重，对比要拉得更开。

**圆角层级**：小控件（标签、复选框）`radius.sm` 4–6；按钮、输入框 `radius.md` 8–12；卡片、弹窗 `radius.lg` 12–20；头像、胶囊按钮 `radius.full`。风格要求直角（如瑞士风、新粗野主义）时统一收紧。`radius.full` 只给一类元素（主按钮或筛选项二选一），标签用 `radius.sm`：满屏胶囊和满屏一样的圆角卡片一样，是没有做形状层级。

**图片**：内容不同的位置用不同的图片，一张照片不要在同一页重复出现；图片原始尺寸不小于显示尺寸。用户给了图片文件或链接时用用户的；没有时用 `design_image({query, orientation, min_width})` 从图库找：`query` 写具体的英文名词短语，每个图位搜一次，看缩略图挑主体清晰、背景干净的一张，把 `url` 写进 `props.src`。交付时在回复里列出用到的图片与署名（`credit`），并提醒用户上线前确认授权或换成自有素材。搜不到合适的或图片搜索已关闭时，用与题材相关的色块加简单图形占位，不要用“渐变底 + 两个字”冒充图片。

## 6. 版式

- **画板宽度**：移动端 390，平板 768，桌面 1440（内容区最大宽度 1200–1280 居中）。
- **不留安全区**：画板顶部与底部不预留状态栏 / Home 指示条的空白高度，内容从画板顶部按正常页边距开始。
- **栅格与边距**：移动端左右边距 16–20；桌面端 12 栏，栏间距 24。同一层级的间距保持一致，区块之间的间距明显大于区块内部。
- **对齐**：一页只用一种主对齐方式，正文左对齐；居中只用于短标题、空状态和单一行动。
- **行宽**：正文每行不超过约 35 个汉字（或 80 个西文字符）。
- **层级**：每屏只有一个视觉焦点。把大胆集中用在一处：让一个元素成为记忆点，周围保持安静克制，删掉不服务于需求的装饰。
- **结构元素是信息**：边框、编号、分隔线、标签要表达内容的真实结构。只有内容确实是步骤或时间线时才用 01 / 02 / 03 编号。

## 7. 组件约定

- 重复出现的块（按钮、列表项、卡片、表单项、tab）都填 `component`，用实例 + `overrides` 区分文本，保证全稿一致。
- **按钮**：高度移动端 44–48、桌面端 36–40；主按钮用 `color.primary` + `color.on-primary`，一屏一个主按钮，其余用次级（描边或浅底）或文字按钮。按钮文字写清楚动作：“保存修改”而不是“提交”。
- **输入框**：高度与按钮一致；标签在框外上方，占位文字只作示例；错误提示在框下方，用 `color.danger`，说明错在哪、怎么改。
- **触控目标**：可点击区域不小于 44×44。
- **列表项**：左侧图标或头像、中间主次两行文字、右侧辅助信息或箭头；行高 56–72，分隔线用 `color.border` 或留白。
- **导航**：移动端底部 tab 栏 3–5 项，选中态用 `color.primary`；顶部导航栏高 44–56。桌面端侧边栏宽 220–260 或顶部导航。
- **状态**：选中、禁用、加载、空、错误状态都画出来，用 `proto`（vars + show / styles / disabled）在同一画板内切换，不复制画板。悬停与按下态写在 `states`。
- **动效**：只在回应用户操作时使用（展开、确认、切换）；不要给每个区块都加入场动画。

## 8. 文案

文字的唯一目的，是让界面更容易理解和使用。

- 从用户的角度命名：用户“管理通知”，而不是“配置 webhook”。说清楚是什么、做什么，不推销。
- 默认主动语态；同一个动作在整个流程里叫同一个名字：按钮是“发布”，提示就是“已发布”。
- 出错和空状态要给方向：说明发生了什么、怎么解决。错误提示不道歉、不含糊；空页面是一个行动入口（“还没有账单，记第一笔”）。
- 口吻平实：动词直接、不用套话，语气匹配品牌与用户群。每段文字只做一件事。
- 中文排版：中英文、中文与数字之间加空格；用全角标点；不要用全大写英文做小标签。

## 9. 质量底线与自检

不用特意声明，但每张稿都要做到：

- 文字对比度达标（正文 ≥ 4.5:1，24px 以上或 18.67px 粗体 ≥ 3:1；控件边框、焦点环、图标 ≥ 3:1），每个主题都要达标；截图自检会逐个文字检查（`low_contrast`）。需要区分的颜色要在明度上拉开，不能只靠色相；状态不只靠颜色区分（配合图标或文字）。
- 移动端可点击元素不小于 44×44（`small_target`）。
- **图标**：线性描边风格，同一稿统一线宽与尺寸，颜色跟随文字色；不用 emoji 当图标。
- 同类元素尺寸、间距、圆角一致；无溢出、截断与重叠。
- 按钮、tab、标签、导航项文字单行显示，不换行、不截断；按钮宽度按最长文案留足左右 padding，空间不够时缩短文案而不是让它折行。
- tab 下划线 / 选中指示条与文字水平居中（tab 项 `layout.align: "center"`），宽度与文字等宽或固定宽度居中；图标与文字在按钮、列表项内垂直居中。
- 截整个画板时，报告末尾附**设计体检**：阶梯外的字号 / 间距 / 圆角、字号档数过多、字重或字体族过多、没有视觉焦点、粗体过多、胶囊过多、卡片套卡片、左侧粗色条卡片、多个主色实心按钮、同一张图重复使用、emoji 图标、“A · B · C” 式元信息、箭头结尾的按钮文字、直接写色值。它们是提醒而不是错误：逐条判断，是这一稿有意的选择就保留并在回复里说明理由，否则修改。
- 每轮结束用 `design_screenshot` 自检：文字报告里的每个问题都要修复后重新截图；报告通过也要对照截图逐项看一遍——文字是否换行或截断、指示条和图标是否居中、同类元素是否一致、边距与对齐线是否统一。有问题就改，改完再截图，直到没有问题。看截图时问自己：第一眼看到的是不是最重要的东西？有没有可以删掉的装饰？像不像任何同类页面都会长成的样子？出门前照照镜子，摘掉一件配饰。
